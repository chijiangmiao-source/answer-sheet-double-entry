# 纸质答题卡双录核对台

纯前端的“双录入核对”工具：同一张固定 20 道单选题的纸质答题卡，由录入员连续录入两遍。系统只在两遍都完整提交后逐题比对——**全部一致才“通过”，否则“不通过”并仅列出差异题**，以此避免复核时惯性照抄第一遍答案导致错误漏检。纸面模糊或有涂改痕迹时，录入员可在不猜测首录内容的前提下为题目加“待复核”标记；标记与答案隔离，不参与裁决，只在不通过的差异行提示对应轮次。

- 技术栈：TypeScript + Vue 3（Composition API）+ Vite
- 无后端、无假接口、无固定响应：题面数据在构建时固定，两轮答案与待复核标记只存在于浏览器内存，刷新即清空
- 批量填入：可粘贴扫描枪 / OCR 文本（A/B/C/D + 空格、逗号、换行），解析出恰好 20 个选项后一次性写入当前轮
- 误触可撤销 / 重做：每轮维护可撤销、可重做的编辑轨迹，鼠标按钮与 `Ctrl/Cmd+Z`、`Ctrl/Cmd+Shift+Z` 共用同一行为（待复核标记不进入轨迹）
- 单元/组件测试：Vitest（85 个用例）
- 端到端测试：Playwright（11 个用例，覆盖通过、不通过、重新开始、批量填入、撤销重做、待复核标记）

## 业务规则

1. 固定 20 道单选题，每题只接受 **A / B / C / D**（大小写均可），其他按键一律忽略。
2. 键盘：
   - `A` `B` `C` `D`：为当前题选择选项，并自动前进到下一题（末题停留在原位）；
   - `↑` `↓` `←` `→`：在题目间前后移动（边界处不越界）；
   - 也可用鼠标直接点选任意题、任意选项；
   - 带 `Ctrl` / `Cmd` 修饰键的字母（如 `Ctrl+A`、`Cmd+C`）属于浏览器/系统快捷键，一律忽略，不会填入当前题。
3. 撤销 / 重做（误触保护）：
   - 每一轮录入都维护一条**编辑轨迹**：只有选项真正发生变化才算一次有效编辑，记录题号、变化前后值与操作前后的焦点；重复选择同一选项、被忽略的按键不进入轨迹；
   - 鼠标“撤销/重做”按钮与 `Ctrl/Cmd+Z`、`Ctrl/Cmd+Shift+Z`（Mac 上 Cmd 同义）共用同一行为；撤销按逆序恢复答案与焦点，重做按原序恢复；
   - 撤销后做出新的选择会**截断重做分支**；轨迹由领域纯函数维护，视图只提交动作并消费返回的答卡、焦点与按钮可用性；
   - **批量整卡覆盖也是轨迹中的一个原子步骤**：一次撤销即可恢复覆盖前整张答卡（含此前已录入的答案），重做再次整体写入；
   - 撤销可能造成漏题，此时提交仍按既有完整性校验在原题原位给出漏答反馈；按钮禁用时快捷键同样不改变答卡；
   - 编辑轨迹只属于当前轮：首录提交、第二轮提交或“重新开始”都会随轮次 `key` 销毁组件而销毁轨迹，第二轮轨迹必为空，任何撤销都不能恢复或暴露首录快照。
4. 批量填入（扫描枪 / OCR）：
   - 在当前轮打开批量填入区，粘贴由 A / B / C / D（大小写均可）及空格、逗号、换行组成的文本；
   - 文本含其他字符时指出**首个非法字符**及其位置，选项数量不是 20 时指出**当前数量**，此时确认不可用、答卡不被部分覆盖；
   - 预览确认恰好 20 个选项后**一次性整体写入**本轮答卡（覆盖已有答案），随后仍可按原流程检查、改单题再提交；该次整体覆盖是一个原子步骤，一次撤销即可恢复覆盖前整卡；
   - 关闭批量填入区不改变任何已录答案。
5. 任一轮存在漏题时**不能提交**：顶部汇总漏答题号，并在每一道漏答题的原位置标注“此题漏答”。
6. 待复核标记（纸面模糊 / 涂改）：
   - 每题题旁有“待复核”按钮，可随时标记、再次点击取消；**标记不进入答案编辑轨迹**：撤销 / 重做、批量整卡写入都不会改变它，标记也不移动焦点、不影响完整性判断；
   - 漏答提交被拦截时，原位漏答错误与已有标记同时保留，补齐后仍按原双录流程提交；
   - 进入下一轮（或“重新开始”）后界面从**空答案、空标记**开始：待复核标记与首录答案一样，第二轮无法提前读取；
   - 每轮提交对象是“答案 + 待复核题号”的**只读冻结记录**，两轮记录分别隔离保存在会话闭包中；**裁决始终只按答案进行**，标记不影响通过与否、一致数与差异集合，只在最终差异项上附带首录、复录各自是否曾标记。
7. 首录完整提交后：
   - 生成**不可修改的内存记录**（答案与标记均对象冻结，且提交时复制，与录入数组隔离）；
   - 界面立即清空并进入第二轮；第二轮的页面内容、焦点（默认第 1 题）、输入状态与标记都不透露、不预填首录选择。
8. 第二轮完整提交后逐题裁决：
   - 两轮完全一致：显示 **“通过”** 与 **20/20**，不展示任何待复核提示；
   - 只要有差异：显示 **“不通过”** 与一致数（如 19/20），并**只列出差异题号及两轮选项**，不展示一致题；仅在不通过的差异行内，对曾标记待复核的那一轮单元格展示“首录待复核”/“第二遍待复核”提示，未标记的轮次与既有差异字段保持原样。
9. 结果页点击“重新开始”：清除两轮状态（含首录记录、两轮标记与裁决结果），返回空白的第一轮。

## 轮次隔离是如何保证的

- 每轮记录（答案 + 待复核标记）保存在 `createSession()`（`src/composables/useSession.ts`）闭包局部变量中，对外 API 只有 `phase / round / verdict / submit / restart`，第二轮组件既无法读取首录答案，也无法提前读取首录标记。
- 第二轮录入视图以轮次为 `key` 整体重新挂载（`src/App.vue`），答题数组、当前焦点、提交状态、**待复核标记**与**编辑轨迹**全部重新初始化为空；首录提交、第二轮提交或“重新开始”都会销毁当前轨迹与标记，任何撤销都无法恢复首录快照。
- 裁决完成后闭包立即释放首录引用；结果对象中只保留差异信息（差异项附带两轮各自的标记位）。

## 测试

```bash
npm run test:unit  # Vitest：轮次隔离、完整性校验、裁决规则、键盘与原位提示、批量解析、编辑轨迹、待复核标记
npm run test:e2e   # Playwright：通过 / 不通过 / 重新开始 / 批量填入 / 撤销重做 / 待复核标记（自动起 preview 服务）
```

Vitest 覆盖：

- 空卡与冻结记录（答案与标记双冻结、与原数组隔离）、漏题即使全标记仍拒绝提交、非布尔真值规范化为 false；
- 一致裁决（通过、20/20）、单题/多题差异（仅列差异、题号升序）、拒绝裁决不完整卡；
- 标记只附带在差异项上（仅首录 / 仅第二遍 / 两轮都标 / 均未标四种组合）、**标记不改变裁决**（答案一致时即使标记不同也通过）、旧提交形态兼容（裸数组、无标记记录、省略标记参数）；
- 会话状态机：两轮状态推进、API 不暴露首录答案与标记、第二轮期间 verdict 为空、第二轮自身标记不被首录污染、漏答拦截后补齐携带原标记、重启清空两轮记录；
- 组件：非法按键忽略、键盘选择与移动、漏题原位提示、补齐后提交、第二轮无预填；
- 待复核组件：每题标记/取消与 aria-pressed 状态、点击标记不移动焦点、标记不进轨迹（仅标记时撤销/重做禁用、录答后撤销/重做不动标记）、批量写入及其撤销不动标记、标记不影响完整性且漏答被拒时标记与原位错误并存、重新挂载即空标记；
- ResultView：不通过时只在被标记轮次的差异格显示提示（仅首录 / 仅第二遍 / 两轮 / 无标记四种情形）、通过页无差异表也无任何提示；
- 编辑轨迹纯函数：有效步骤记录题号/前后值/操作前后焦点、逆序撤销与原序重做（含焦点恢复）、重复选择与越界等无效动作不留痕、撤销后新选择截断重做分支、焦点移动不污染轨迹、批量整卡覆盖作为单个原子步骤可一次撤销恢复覆盖前整卡、重新初始化即跨轮清空；
- 撤销/重做组件：鼠标按钮与 Ctrl/Cmd+Z、Ctrl/Cmd+Shift+Z 同行为、Ctrl/Cmd+字母组合不误填、禁用态快捷键不改答卡、撤销造成漏题原位拦截且重做补齐后可提交、批量覆盖后撤销恢复覆盖前已录答案、第二轮挂载轨迹为空且快捷键无法恢复首录；
- 批量解析纯函数：分隔符（空格/逗号/换行）归一化、大小写规范化、首个非法字符定位、数量校验（0/19/21）；
- 批量填入组件：合法文本原子写入 20 题并可继续单题修改、非法输入禁用确认且答卡不被部分覆盖、关闭填入区不改已录答案、输入框按键不触发答题。

Playwright 覆盖：

1. 两轮 20 题一致 → “通过” + 20/20，且第二轮初始为空白、焦点在第 1 题；
2. 第二轮第 3 题不同 → “不通过” + 19/20，差异表只有第 3 题一行（首录 A / 第二遍 B）；
3. 首录漏第 20 题被拦截并原位提示，补齐走完两轮后“重新开始”，确认回到无任何选择与结果的空白首录；
4. 两轮分别批量填入相同文本 → “通过” + 20/20，第二轮批量填入前仍为空白；
5. 无效文本（非法字符 / 数量不足）被拒绝且答卡保持全空，关闭填入区后用键盘补录两轮 → “不通过” + 19/20，差异表只有第 5 题一行；
6. 误触后鼠标撤销、重做（并混用 Ctrl/Cmd 快捷键），再录完两轮逐题一致 → “通过” + 20/20，第二轮新轨迹为空；
7. 撤销至第 18/19/20 题漏答被原位拦截，补录完成后第二轮录成第 10 题差异 → 仍按既有规则“不通过” + 19/20，差异表只有第 10 题一行；
8. Ctrl/Cmd+字母不误填当前题；批量整卡覆盖后一次撤销恢复覆盖前已录答案（1=A、2=B，其余空），重做再次整体写入；
9. 两轮标记不同且答案仅一处差异：差异表只有该差异行，且**只在该行显示曾标记轮次的提示**；首录标在一致题上的标记不出现；第二轮初始 20 题均无标记（无泄露）；
10. 两轮都标记同一差异题 → 差异行同时显示“首录待复核”与“第二遍待复核”两个提示；
11. 首录漏答被拦截时原位错误与标记（含漏答题上的标记）同时保留，补齐提交后第二轮空答案空标记，答案一致走通通过页且无任何提示，“重新开始”后答案、标记、漏答反馈与结果全部清空。

## Docker Compose

提供两个服务（`docker-compose.yml`）：

### 静态 Web

```bash
docker compose up -d --build web
# 默认 http://localhost:8080
```

宿主端口可用 `WEB_PORT` 覆盖：

```bash
WEB_PORT=9000 docker compose up -d web
# http://localhost:9000
```

Web 镜像（`Dockerfile`）多阶段构建：Node 构建静态资源，nginx:alpine 托管 `dist/`，SPA 路径回退到 `index.html`。

### 一次性验收服务 verify

```bash
docker compose build verify
docker compose run --rm verify
```

容器内串行执行 **Vitest 单测 → Playwright 端到端测试**，全部通过退出码为 0，任一失败为非零；进程结束即退出（`restart: "no"`），不会常驻。基于官方 Playwright 镜像（`mcr.microsoft.com/playwright:v1.49.1-jammy`），浏览器与系统依赖均已预装。

## 目录结构

```
src/
  data/questions.ts        # 固定 20 道单选题（仅题面，无答案）
  core/types.ts            # 领域类型（答案、待复核标记、轮次记录、裁决）
  core/scoring.ts          # 纯函数：空卡、轮次记录冻结提交、逐题裁决（只按答案，差异附带标记）
  core/history.ts          # 纯函数：每轮可撤销/重做的编辑轨迹（记录、撤销、重做、焦点）
  core/batchParse.ts       # 纯函数：批量文本规范化、位置映射、组合解析
  composables/useSession.ts# 两轮状态机与首录记录（答案+标记）隔离
  components/RoundView.vue # 单轮录入（键盘/鼠标/批量填入、撤销重做、漏题原位提示）
  components/ResultView.vue# 裁决结果与差异明细
tests/unit/                # Vitest
tests/e2e/                 # Playwright
Dockerfile / Dockerfile.verify / nginx.conf / docker-compose.yml
```
